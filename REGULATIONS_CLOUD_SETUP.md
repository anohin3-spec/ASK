# Настройка облачного хранения регламентов в Supabase

## Шаг 1: Выполните SQL миграцию

1. Откройте [Supabase Dashboard](https://supabase.com/dashboard)
2. Перейдите в ваш проект
3. Откройте **SQL Editor** в боковом меню
4. Скопируйте содержимое файла `migration_add_regulations.sql`
5. Вставьте в редактор и нажмите **Run**

Это создаст таблицу `regulations` для хранения метаданных регламентов.

## Шаг 2: Создайте Storage bucket для регламентов

### Вариант A: Автоматическое создание (рекомендуется)

Bucket будет создан автоматически при первом запуске программы в облачном режиме.

### Вариант B: Создание вручную

1. В Supabase Dashboard откройте раздел **Storage**
2. Нажмите **Create a new bucket**
3. Введите имя: `regulations`
4. Настройки:
   - **Public bucket**: ✅ Включите (чтобы файлы были доступны по ссылкам)
   - **File size limit**: 50 MB (достаточно для PDF регламентов)
   - **Allowed MIME types**: оставьте пустым (разрешить все типы)
5. Нажмите **Create bucket**

## Шаг 3: Настройте политики доступа к Storage

Выполните следующий SQL для настройки политик bucket:

```sql
-- Разрешить всем авторизованным пользователям читать регламенты
CREATE POLICY "Регламенты доступны для чтения всем"
ON storage.objects FOR SELECT
USING (
    bucket_id = 'regulations' AND 
    auth.role() = 'authenticated'
);

-- Разрешить админам загружать регламенты
CREATE POLICY "Админы могут загружать регламенты"
ON storage.objects FOR INSERT
WITH CHECK (
    bucket_id = 'regulations' AND 
    (
        auth.jwt() ->> 'role' = 'admin' OR 
        auth.jwt() ->> 'role' = 'superadmin'
    )
);

-- Разрешить админам удалять регламенты
CREATE POLICY "Админы могут удалять регламенты"
ON storage.objects FOR DELETE
USING (
    bucket_id = 'regulations' AND 
    (
        auth.jwt() ->> 'role' = 'admin' OR 
        auth.jwt() ->> 'role' = 'superadmin'
    )
);

-- Разрешить админам обновлять регламенты
CREATE POLICY "Админы могут обновлять регламенты"
ON storage.objects FOR UPDATE
USING (
    bucket_id = 'regulations' AND 
    (
        auth.jwt() ->> 'role' = 'admin' OR 
        auth.jwt() ->> 'role' = 'superadmin'
    )
);
```

## Шаг 4: Проверка настройки

1. Запустите программу
2. Откройте вкладку **"История ТО"**
3. Нажмите кнопку **"Регламенты"**
4. Добавьте любой PDF файл для любого типа техники
5. Проверьте, что файл появился в Supabase Storage → regulations

## Поддерживаемые форматы файлов

- **PDF** (.pdf) - рекомендуется
- **Word** (.doc, .docx)
- **Excel** (.xls, .xlsx)
- **Изображения** (.png, .jpg, .jpeg)

## Синхронизация между пользователями

✅ **Файлы регламентов синхронизируются автоматически:**

- Администратор добавляет регламент → **все видят обновление**
- Администратор изменяет регламент → **все получают новую версию**
- Администратор удаляет регламент → **он пропадает у всех**

При открытии диалога "Регламенты" программа всегда получает актуальный список из облака.

## Права доступа

### Чтение регламентов:
- ✅ Все авторизованные пользователи

### Управление регламентами (добавление/удаление):
- ✅ Администраторы (admin)
- ✅ Суперадминистраторы (superadmin)
- ❌ Менеджеры (manager)
- ❌ Обычные пользователи (user)

## Устранение проблем

### Ошибка: "Не удалось добавить файл регламента"

**Причина 1:** Bucket 'regulations' не создан
- **Решение:** Создайте bucket вручную (см. Шаг 2)

**Причина 2:** Недостаточно прав
- **Решение:** Убедитесь что вы вошли как администратор

**Причина 3:** Не настроены Storage политики
- **Решение:** Выполните SQL из Шага 3

### Окно регламентов пустое

**Причина:** Таблица regulations не создана
- **Решение:** Выполните миграцию из Шага 1

### Файл не открывается

**Причина 1:** Проблема с интернет-соединением
- **Решение:** Проверьте подключение к интернету

**Причина 2:** Файл был удален из Storage
- **Решение:** Загрузите регламент заново

## Резервное копирование

1. Откройте Supabase Dashboard → Storage → regulations
2. Скачайте все файлы на компьютер
3. Экспортируйте таблицу regulations:
   ```sql
   SELECT * FROM regulations;
   ```
4. Сохраните результат

### Восстановление:

1. Загрузите файлы обратно в bucket через Storage интерфейс
2. Восстановите записи в таблице через SQL Editor

## Ограничения

- **Размер файла:** Максимум 50 MB (настраивается в bucket settings)
- **Количество файлов:** По одному на каждый тип техники (4 типа = 4 файла)
- **Формат имени:** Автоматически генерируется из типа техники

## Рекомендации

1. **Используйте PDF формат** - универсален и не требует дополнительного ПО
2. **Называйте файлы понятно** перед загрузкой: "Регламент_Камаз_2024.pdf"
3. **Обновляйте регламенты** при получении новых версий от производителя
4. **Информируйте пользователей** о загрузке новых регламентов
